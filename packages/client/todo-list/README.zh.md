# dsh-client-todo-list

[English](README.md) | 中文

一个贡献到 Web 设置面板顶层**待办**页签的待办清单功能。Host 半边注册 `todo-list` 设置命名空间，并将解析值持久化到 `<项目根目录>/.data/todo-list/todos.json`；浏览器半边渲染一个设置页面（不是插件选项卡片），通过该命名空间管理分级清单——任务之下是带顺序的清单，每个清单下是带顺序的条目。

## 如何呈现

浏览器半边以导航 id `todo`（`order: 5`，位于通用与模型之间）注册 `settings.section`，因此它会渲染为设置左侧栏与通用 / 模型 / 插件并列的顶层入口，而非插件选项卡片。只有当本插件的 Host 半边被组合进来时该页面才会出现，因为浏览器端只有此时才被提供 `todo-list` 设置命名空间。每次操作都通过客户端设置作用域写回，因此新增 / 勾选 / 删除 / 排序都会立即落到 Host，页面通过作用域快照保持实时。

## 数据模型与层级

- **任务**：包含一个或多个清单，带序号并可拖拽排序；内置**日常任务**，创建后不可删除。
- **清单**：从属于某个任务，在任务内带序号并可拖拽排序。
- **条目**：从属于某个清单，在清单内带序号并可拖拽排序，可勾选、删除、清除已完成。

旧的扁平格式（`{ items: [...] }`）会在启动时自动迁移到内置“日常任务”中成为其第一张清单，因此历史条目会被保留。

## 存储

Host 半边拥有持久化文档 `<项目根目录>/.data/todo-list/todos.json`。每次 `todo-list` 命名空间发生提交都会把解析值写入该文件；启动时若文件与当前值不一致，会从文件回填命名空间（并在该读取时执行迁移），因此该文件是权威、可手工编辑的副本。项目根目录默认取进程启动目录（`process.cwd()`），可用插件配置键 `root` 覆盖。

## 配置

- `root` - `data` 目录所在的项目根目录；默认取启动目录。

## 模型体验

无；这是一个浏览器配置界面，不产生任何模型调用。

## 已知限制

- 文件为权威来源：`todo-list` 段也会同时写入共享设置文档，但启动时文件优先并回填命名空间，因此应编辑 `todos.json` 而不是设置文件里的 `todo-list:` 段。
- 外部编辑仅重启时读取：Host 半边不监听该文档，因此非本进程对 `todos.json` 的改动需在下次启动才生效。
- 拖拽排序使用原生 HTML5 拖拽事件：支持鼠标或触控板，未提供纯键盘排序。
