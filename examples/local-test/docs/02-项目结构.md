# 02 · 项目结构

> 这个仓库是一个 **pnpm monorepo**。真实可发货的代码在 `packages/`(234 个 `@deepseek-ai/dsh-<name>` workspace 包),启动入口在 `apps/`,核心框架在 `vendor/`。

## 顶层布局

```
deepseek-harness/
├── packages/     # 所有功能包,按能力分组(核心,研究重点)
├── apps/         # 可执行入口: cli(命令行 dsh) + web(Web UI)
├── vendor/       # 被 vendored 的 Cordis 框架源码 + 同步清单(manifest)
├── docs/         # 官方文档(权威,与源码 type-equiv 强一致)
├── examples/     # 可运行的 cordis.yml「叶子」示例 + 包级 demo bundles
├── scripts/      # 仓库闸门与代码生成器(run-gates.ts 等)
├── website/      # VitePress,把双语 docs + i18n 投影成网站
├── python/       # Python SDK 与内置运行时
├── native/       # @deepseek-ai/node-addon-landlock-run 源
└── 根配置文件      package.json / tsconfig*.json / vitest*.config.ts / lefthook.yml ...
```

## 关键根文件

| 文件 | 作用 |
|---|---|
| `AGENTS.md`(根的 `CLAUDE.md` 软链到它) | **全项目最高约定** —— 先读它再动 `packages/` |
| `package.json` | workspace 脚本(`dsh` bin、test/typecheck/lint/build/hygiene...)、pnpm 版本 |
| `pnpm-workspace.yaml` | workspace 分组映射 |
| `tsconfig.json` | solution root,仅 `files: []` + 引用两个 aggregate |
| `tsconfig.host.json` / `tsconfig.client.json` | **Host / Client 双 aggregate** 程序 |
| `tsconfig.base.json` | 共享 compilerOptions + 源码 `paths` 映射(无 include) |
| `.nvmrc` | 固定 Node 版本信号(本机用 v22.23.2) |

> **一个常见困惑**:为什么有 Host / Client 双 aggregate?因为 Host 和 Client 两侧都会用声明合并往同一个 `Context` 接口注服务键;若合成一个 `ts.Program` 会「合并冲突」。所以在同一个程序里看不到两边 —— 模块解析不受影响,只有编译期需要分开。

## packages/ 分组明细

`packages/` 下的第一层目录就是「能力分组」。每个组内是 `dsh-<name>` 包,一个包 = 一个插件/一组关联插件。

### core/ —— 产品 API 主轴(学习主线,记住 ctx 键)
```
agent               ctx.agents       Agent 接口、活注册表、agent/* 事件
agent-loop          ctx.agentLoop    实现上面的默认驱动(循环)
agent-default-model / agent-tool-presentation
scope                                       每 agent 作用域的注册原语(无 ctx 键)
session             ctx.sessions     追加式 SessionEvent 日志 + 内存态存储
system-prompt       ctx.systemPrompt 提示词分节 + 工具 schema 组装
tools               ctx.tools        作用域工具注册 + 守卫执行管线
```

## apps/ —— 真正的主进程入口

`apps/` 不是普通包,是「把包组装的 profile 树拉起来跑」的 launcher。

```
apps/cli/src/
  bin.ts           # dsh 命令入口: parseDshArgs → switch(mode)
  args.ts          # 参数解析
  profile-boot.ts  # 核心: 解析 profile → 叠 patch → boot() 拉起插件树
  plugin.ts        # dsh plugin(单独挂一个插件)
  dump-config.ts   # --dump-config
  process-shutdown.ts
apps/web/          # Web UI 相关的构建产物宿主(真正的浏览器应用逻辑在 packages/web / client)
```

`dsh` bin 定义在根 package.json:`"dsh": "node --import tsx/esm apps/cli/src/bin.ts"` —— 源码直接通过 **tsx 的 ESM hook** 跑,所以它触达的模块必须保持 ESM。

## vendor/ —— Cordis 框架(内部真相)

```
vendor/README.md    # 上游 SHAs + 同步(升级)流程
vendor/src/         # @deepseek-ai/cordis 的 vendored 源码: context.ts / registry / loader ...
```

「一切皆插件」的根基就在这里:**`Context`(服务仓库)、`ctx.on/effect/waterfall/parallel/serial`、Loader、`cordis-plugin-*`(logger、timer、hmr、include、loader、inspect...)**。改 vendor 代码要按 `vendor/README.md` 流程走(manifest 守卫)。

## .agents/ 与 .claude/ —— 面向代理的工程

```
.agents/notes/        Agent Notes 归档(implemented/advisor/archive; 归档的冻结不可改动) —— 每个非平凡改动的「决策为何如此」都在这
.agents/skills/       dsh-pre-push-checks / dsh-code-review / dsh-doc-standards ... 仓库专用技能
.claude/              本地 Claude/编辑器配置(settings 等)
```

> 想让 Claude/你自己顺手用这些,读 `.agents/skills/*/SKILL.md`。贡献前记得 `.agents/notes/README.md` 的「何时写 Agent Note」规则。
